# Security and vulnerability disclosure

GrimmDiff accepts vulnerability reports from users, researchers, and customers. The commercial release owner must publish a monitored security contact address before the first market release; no public release is approved without it.

## Reporting and response

Reports must include affected version, reproduction steps, impact, and any proof of concept. The security owner acknowledges reports within two business days, completes initial triage within five business days, and communicates the remediation plan to the reporter.

The security owner assigns a severity, opens a confidential incident record, tracks the fix, and coordinates disclosure with the reporter. Security fixes receive an advisory containing affected versions, severity, mitigation, fixed version, and CVE where assigned. Public disclosure occurs after a fix is available unless delayed disclosure is required to protect users.

For actively exploited vulnerabilities and severe incidents, the security owner follows `docs/security/incident-response.md`, including the CRA Single Reporting Platform deadlines.

## Supported releases

Each commercial release must state its support end date in the release notes and user documentation. Security fixes are supplied for supported releases only. The first commercial release is blocked until a support-period policy and a monitored security contact are approved by the manufacturer.
